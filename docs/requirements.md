# MyMail 요구사항 정의서

> 로컬 사본 (2026-10-09 기준). 원본: [Claude Docs](https://claude.ai/code/artifact/b1969ba7-ba7b-4db1-b06f-ed97e49959ab). 원본이 바뀌면 이 파일도 갱신한다.

## 1. 개요

MyMail은 Gmail과 네이버 메일 계정을 여러 개 등록하고, 사이드바에서 계정을 눌러 해당 계정의 메일을 보고 보내는 Windows 데스크톱 메일 클라이언트다.

- 플랫폼: Windows 10/11 64비트 (가정)
- 지원 서비스: Gmail 개인 계정(@gmail.com), 네이버 메일(@naver.com)
- UI 언어: 한국어만
- 대상 사용자: 본인과 지인 몇 명 (Google 미검수 상태로 사용, 2장 참고)

| 구분 | 내용 |
| --- | --- |
| MVP | 다중 계정 등록, 사이드바 계정 전환, 폴더·라벨 탐색, 읽기·작성·답장·전달, 첨부, 계정 내 검색, 새 메일 알림, 통합 받은편지함 |
| 2차 | 통합 검색, 발송 취소·예약 발송, 키보드 단축키, 폴더 관리, 주소록 |
| 범위 외 | 캘린더·연락처 앱, 모바일·macOS, Google Workspace(회사·학교) 계정, Gmail·네이버 외 메일 서비스 |

## 2. 계정 관리

Gmail은 OAuth 브라우저 로그인으로, 네이버는 IMAP/SMTP 아이디·비밀번호로 연결하고, 두 방식 모두 같은 계정 추가 화면에서 처리한다.

| 서비스 | 접속 방식 | 인증 | 사용자 사전 설정 |
| --- | --- | --- | --- |
| Gmail | Gmail API (권장) | OAuth 2.0, 기본 브라우저에서 Google 로그인 | 없음 |
| 네이버 | IMAP imap.naver.com:993 (SSL), SMTP smtp.naver.com:465 (SSL) | 아이디 + 비밀번호, 2단계 인증 사용 시 애플리케이션 비밀번호 | 네이버 메일 환경설정 > POP3/IMAP 설정에서 IMAP 사용 켜기 |

**Gmail 연동 주의:** 메일 읽기·수정 권한은 Google의 '제한된 범위'라, 불특정 다수에게 배포하려면 Google 앱 검수와 정기 보안 평가를 통과해야 한다. 개인용이나 소수 사용자용이면 미검수 상태(로그인 시 경고 화면)로 쓸 수 있다. IMAP으로 연결해도 같은 권한이 필요해 이 제약은 피할 수 없다.

**개인용 설정:** Google Cloud 프로젝트의 OAuth 동의 화면을 '프로덕션'으로 게시하고 검수는 신청하지 않는다. '테스트' 상태로 두면 7일마다 다시 로그인해야 한다. 미검수 앱은 사용자 100명까지 쓸 수 있고, 처음 로그인할 때 '확인되지 않은 앱' 경고가 한 번 뜬다.

- ACC-01 계정 추가 마법사: 서비스 선택(Google/네이버) → 인증 → 표시 이름·계정 색 지정 → 초기 동기화 진행 표시
- ACC-02 등록 계정 수 제한 없음, 같은 서비스 계정 여러 개 허용
- ACC-03 사이드바 계정 항목: 서비스 아이콘, 표시 이름, 메일 주소, 안 읽은 메일 수 배지
- ACC-04 계정 클릭 시 해당 계정의 폴더·라벨 트리를 펼치고 받은편지함을 연다
- ACC-05 계정 순서 드래그 변경, 사이드바에서 숨기기
- ACC-06 계정별 설정: 표시 이름, 보낸사람 이름, 서명, 알림 켜기/끄기, 동기화 주기
- ACC-07 계정 제거 시 확인 후 해당 계정의 로컬 캐시·자격 증명 삭제
- ACC-08 토큰 만료·비밀번호 변경으로 인증이 실패하면 사이드바 계정에 경고 표시 + 재로그인 버튼
- ACC-09 네이버 로그인 실패 시 IMAP 활성화·애플리케이션 비밀번호 발급 방법 안내

## 4. 비기능 요구사항

비밀번호·토큰은 OS 암호화 저장소에만 저장하고, 최근 메일은 로컬에 캐시해 오프라인에서도 읽을 수 있게 한다. 성능 수치는 제안값이다.

| 분류 | 요구사항 |
| --- | --- |
| 보안 | 비밀번호·OAuth 토큰은 Windows 자격 증명 관리자에 암호화해 저장, 평문 저장 금지 |
| 보안 | 서버 연결은 TLS만 허용 |
| 보안 | HTML 메일의 스크립트 실행 차단, 외부 이미지는 기본 차단(보낸사람별 허용) |
| 동기화 | 최초 동기화 범위: 전체 메일. 최근 메일부터 받아 먼저 보여주고 나머지는 백그라운드로 받으며, 앱을 다시 켜도 이어서 받는다. 첨부 파일은 열 때 내려받는다(제안) |
| 동기화 | 새 메일 감지: Gmail은 변경 내역 주기 조회, 네이버는 IMAP IDLE(미지원 시 주기 조회), 기본 주기 1분 |
| 동기화 | 앱에서 한 읽음·삭제·이동은 서버에 반영되고, 웹메일에서 한 변경도 앱에 반영 |
| 오프라인 | 캐시된 메일 열람, 오프라인 작성 메일은 보낼 편지함에 두었다가 연결 시 발송 |
| 성능 | 앱 시작 후 3초 안에 마지막 화면 표시, 계정 전환 0.5초 이내(캐시 기준) |
| 성능 | 메일 10만 건 폴더도 끊김 없이 스크롤(목록 가상화) |
| 시스템 | 창을 닫아도 트레이에 상주하며 알림 수신, Windows 시작 시 자동 실행 옵션 |
| 시스템 | Windows 라이트/다크 모드 연동, 고해상도(150%·200% 배율) 대응 |
| 접근성 | 키보드만으로 모든 기능 사용, 내레이터(화면 읽기 프로그램) 레이블 제공 |

## 5. 기술 스택 및 아키텍처

Tauri 2 + React + TypeScript로 확정했다. UI는 웹 기술로, 메일 처리·저장·인증은 Rust 코어에서 맡고, 설치 파일과 메모리 사용량이 Electron보다 훨씬 작다.

| 영역 | 선택 | 이유 |
| --- | --- | --- |
| 앱 셸 | Tauri 2 | Windows 내장 WebView2 사용, 알림·트레이·자동 실행·업데이트 플러그인 제공 |
| UI | React + TypeScript (Vite) | 모던 웹앱 스타일 구현, 컴포넌트 재사용 |
| 코어 언어 | Rust | 메일 동기화·저장·인증을 UI와 분리해 처리 |
| Gmail 연동 | Gmail REST API(reqwest) + OAuth 2.0 PKCE(oauth2 크레이트), 시스템 브라우저 로그인 | 라벨·스레드·검색을 서버 기능 그대로 사용 |
| 네이버 연동 | async-imap(IMAP) + lettre(SMTP) | Rust에서 널리 쓰이는 IMAP·SMTP 라이브러리 |
| 메일 파싱 | mail-parser | MIME·첨부·한글 인코딩(EUC-KR 등) 처리 |
| 본문 표시 | 샌드박스 iframe + DOMPurify | 스크립트 차단, 외부 이미지 차단 제어 |
| 로컬 저장 | SQLite (rusqlite) + FTS5 | 메일 캐시, 본문 전체 텍스트 검색 |
| 자격 증명 | keyring 크레이트 | Windows 자격 증명 관리자에 토큰·비밀번호 저장 |
| 배포 | Tauri 번들러(NSIS 설치 파일) + updater 플러그인 | 지인에게 설치 파일 전달, 자동 업데이트 |

주의할 점: Rust 메일 라이브러리는 Node·.NET보다 덜 성숙해, 한글 폴더 이름 인코딩(IMAP modified UTF-7)이나 네이버 서버 응답 차이를 직접 처리해야 할 수 있다. 막히면 메일 처리만 Node 사이드카(ImapFlow)로 분리하는 방법이 있다.

구조 (3계층 + 외부 서버):

```
UI (React, Tauri 웹뷰)        사이드바(계정·폴더) | 메일 목록 | 읽기 창 | 작성 창
        ↓ invoke
앱 서비스 (Rust, Tauri 코어)   계정 관리 | 동기화 엔진 | 발송 큐 | 검색·알림
        ↓
공통 메일 인터페이스(MailProvider)
  Gmail 어댑터 (Gmail REST API + OAuth 2.0)  → HTTPS → Gmail 서버
  네이버 어댑터 (async-imap · lettre)          → IMAP·SMTP(TLS) → 네이버 메일 서버
  로컬 저장소 (SQLite 캐시 · 자격 증명 관리자)
```

UI와 앱 서비스는 공통 인터페이스만 알고, Gmail API와 IMAP의 차이는 각 어댑터가 처리한다. 나중에 다른 메일 서비스를 추가할 때도 어댑터 하나만 만들면 된다.

## 6. 디자인 요구사항 (Claude Design 전달용)

모던 웹앱 스타일의 4단 레이아웃(계정 레일 · 폴더 · 목록 · 본문)으로, 라이트·다크 모드의 화면 7개를 디자인한다.

### 6.1 디자인 방향

참고 제품은 Superhuman, Spark, Linear처럼 장식을 줄이고 여백과 글자 굵기로 위계를 주는 미니멀 웹앱이다.

1. 메일 내용이 주인공: 테두리·그림자·색 면을 최소화하고 여백과 타이포그래피로 구분한다.
2. 계정 색으로 구분: 계정마다 고유 색을 정해 계정 레일 아바타, 폴더 패널 상단, 작성 창의 보내는 계정에 일관되게 쓴다.
3. 키보드 우선: 주요 버튼의 툴팁에 단축키를 함께 표시한다.
4. 라이트·다크 모드를 똑같이 완성도 있게 만든다.

### 6.2 레이아웃

| 영역 | 기본 크기 | 내용·동작 |
| --- | --- | --- |
| 타이틀 바 | 높이 40px | 프레임 없는 창. 왼쪽 MyMail 로고, 가운데 검색창, 오른쪽 동기화 상태·설정·창 버튼(최소화·최대화·닫기) |
| ① 계정 레일 | 너비 64px 고정 | 맨 위 통합 받은편지함(전체) 아이콘, 그 아래 계정 아바타 세로 나열, 아래쪽에 계정 추가(+)·설정 |
| ② 폴더 패널 | 너비 220px (180~320 조절) | 선택 계정 이름·주소, 새 메일 버튼, 기본 폴더, 사용자 폴더·라벨 트리. 접기 가능 |
| ③ 메일 목록 | 너비 360px (300~520 조절) | 필터·정렬 툴바 + 메일 목록 |
| ④ 본문 | 나머지 (최소 480px) | 메일 읽기, 답장 시 하단에 인라인 작성기 |

창 너비가 1280px 미만이면 폴더 패널이 아이콘만 남기고 접히고, 1024px 미만이면 본문이 목록 위로 겹쳐 열린다. 최소 창 크기는 960×600px다.

**패널 너비 조절:** 폴더 패널·메일 목록·본문 사이 경계를 마우스로 좌우로 끌어 너비를 바꾼다. 경계에 마우스를 올리면 좌우 화살표 커서와 2px 강조선이 보이고, 더블클릭하면 기본 너비로 돌아간다. 각 패널은 최소 너비까지 줄어들고, 폴더 패널을 최소 너비보다 더 끌면 아이콘만 남기고 접힌다. 조절한 너비는 저장해 다음 실행 때 그대로 연다. 계정 레일은 64px 고정이다.

### 6.4 컴포넌트

| 컴포넌트 | 요구사항 |
| --- | --- |
| 계정 아바타(레일) | 40px 원형, 프로필 사진 또는 이니셜, 계정 색 링. 오른쪽 아래 서비스 배지(Google/네이버), 오른쪽 위 안 읽은 수 배지(99+). 선택 시 왼쪽 세로 막대, 호버 시 메일 주소 툴팁, 인증 오류 시 경고 표시 |
| 폴더 항목 | 아이콘 + 이름 + 안 읽은 수. 선택·호버 상태, 라벨은 색 점 |
| 메일 목록 행 | 안 읽음 점, 보낸사람(안 읽음이면 굵게), 시간, 제목, 미리보기 1줄, 첨부·별표·라벨 칩. 호버 시 체크박스와 빠른 동작(보관·삭제·읽음·별표). 밀도: 기본(3줄) / 컴팩트(1줄). 통합 받은편지함에서는 행 왼쪽에 계정 색 세로선 |
| 일괄 작업 바 | 여러 개 선택 시 목록 툴바가 선택 수 + 보관·삭제·이동·읽음·스팸으로 바뀜 |
| 본문 헤더 | 제목, 보낸사람 아바타·이름·주소, 받는사람(펼치기), 시간, 동작 버튼(답장·전체 답장·전달·보관·삭제·더보기) |
| 스레드 | 이전 메일은 한 줄로 접히고 클릭하면 펼침 |
| 외부 이미지 배너 | 본문 위 "이미지가 차단되었습니다 · 표시 · 이 보낸사람은 항상 표시" |
| 첨부 카드 | 파일 형식 아이콘, 이름, 크기, 미리보기·저장 버튼, 모두 저장 |
| 작성기 | 보내는 계정 드롭다운(계정 색), 주소 칩 + 자동완성 목록, 서식 툴바, 첨부 영역(드래그 앤 드롭 표시), 보내기 버튼 + 예약 메뉴, 임시저장 상태 문구 |
| 토스트 | 화면 하단 "보관함으로 이동 · 실행 취소", "보내는 중… · 취소" |

### 6.5 상태

| 상태 | 표시 |
| --- | --- |
| 로딩 | 목록·본문 스켈레톤 |
| 빈 폴더 | 짧은 문구만 ("받은편지함이 비었습니다") |
| 메일 미선택 | 본문 영역에 자주 쓰는 단축키 힌트 |
| 동기화 중 | 타이틀 바 동기화 아이콘 회전, 툴팁에 마지막 동기화 시각. 최초 전체 동기화 중에는 폴더 패널 하단에 진행률(받은 메일 수 / 전체) |
| 오프라인 | 상단 얇은 배너 "오프라인 · 보낼 편지함 n개 대기" |

| 발송 실패 | 토스트 + 보낼 편지함에 실패 표시, 다시 보내기 버튼 |

### 6.7 인터랙션

- 단축키(Gmail 방식): c 새 메일, r 답장, a 전체 답장, f 전달, e 보관, # 삭제, / 검색, j·k 다음·이전 메일, Ctrl+1~9 계정 전환, Ctrl+Enter 보내기
- 메일을 폴더·라벨로 드래그해 이동, 파일을 작성기로 드래그해 첨부
- 목록 행·폴더·계정 아바타 우클릭 메뉴
- 폴더·목록·본문 패널 경계를 좌우로 드래그해 너비 조절(더블클릭 시 기본 너비), 다음 실행 때 그대로 유지
