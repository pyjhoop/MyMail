# Claude Code 개발 가이드

핵심 세 가지:

1. Claude가 매번 다시 알아내야 하는 걸 파일로 남긴다.
2. 한 세션에서는 작업 하나만 한다.
3. 결과는 말이 아니라 테스트로 확인한다.

## 1. 하네스 구성 (이 리포에 이미 있음)

```
MyMail/
├─ CLAUDE.md              매 세션 자동으로 읽힘. 짧게 유지(100줄 이내)
├─ docs/
│  ├─ requirements.md     요구사항 로컬 사본
│  ├─ plan.md             마일스톤·체크리스트 (진행 상황의 기준)
│  ├─ decisions.md        결정 로그
│  └─ design/             디자인 산출물
├─ src/CLAUDE.md          React 규칙 (src/ 작업 때만 읽힘)
├─ src-tauri/CLAUDE.md    Rust 규칙 (src-tauri/ 작업 때만 읽힘)
└─ .claude/
   ├─ settings.json       권한 허용 목록, 자동 포맷 훅
   ├─ hooks/format.mjs    수정한 파일 자동 포맷 (prettier, rustfmt)
   └─ skills/verify/      /verify: 타입·린트·테스트·clippy 한 번에
```

- **CLAUDE.md는 짧게.** 매 세션 맨 앞에 통째로 들어가므로 길수록 매번 토큰을 쓴다. 상세 내용은 `docs/`에 두고 경로만 적는다.
- **폴더별 CLAUDE.md.** 해당 폴더 파일을 다룰 때만 읽혀서 컨텍스트가 준다.
- **요구사항은 리포 안에.** Claude Docs 링크를 매번 읽게 하는 것보다 로컬 마크다운이 싸고 빠르다. 원본이 바뀌면 사본도 갱신한다.
- **디자인 산출물.** Claude Design 캔버스의 화면 파일(`.dc.html`)과 토큰을 `docs/design/`에 내려받아 두면 정확한 수치를 보고 구현할 수 있다.
- **자동 포맷 훅.** 스타일 수정에 토큰을 쓰지 않게 한다.
- **권한 허용 목록.** `pnpm`, `cargo`, git 조회 명령은 확인 없이 실행된다.

## 2. 개발 순서

`docs/plan.md`의 M0~M7을 순서대로 진행한다. M0~M2는 실제 메일 계정 없이 가짜 데이터로 진행한다.

`FakeProvider`를 먼저 만들어 두면 UI 작업 때마다 실서버에 붙지 않아도 되고 테스트도 빠르다.

## 3. 명령하는 법

- **큰 기능은 계획 모드부터.** `Shift+Tab`으로 계획 모드에 들어가 계획을 받고, 확인한 뒤 구현시킨다. 잘못된 방향으로 코드를 많이 쓰는 게 토큰을 가장 많이 날린다.
- **범위·완료 기준·금지 사항을 같이 준다.**

  ```
  docs/plan.md의 M3 "폴더 목록" 작업을 해줘.
  범위: src-tauri/src/providers/naver.rs
  완료 기준: 한글 폴더명 디코딩 단위 테스트 포함, /verify 통과
  하지 말 것: UI 수정, 다른 Provider 수정
  ```

- **파일 경로를 직접 짚는다.** `@src/features/mail-list/MailList.tsx`처럼 주면 탐색 비용이 사라진다.
- **작업이 끝나면 `/clear`.** 세션이 길수록 매 요청마다 이전 대화 전체가 다시 들어간다. 순서: plan.md 체크 → 커밋 → `/clear`.
- **모델 나누기.** 설계·어려운 디버깅은 Opus, 반복 구현은 Sonnet. 계획 모드에서만 Opus를 쓰는 `opusplan`도 있다(`/model`).
- **로그는 필요한 부분만.** 에러 전체 대신 핵심 몇 줄이나 로그 파일 경로를 준다.
- **서브에이전트·`/code-review`는 마일스톤 끝에만.** 서브에이전트는 컨텍스트를 처음부터 다시 쌓아서 비싸다.

## 4. 사용자가 직접 해야 할 일

1. Gmail: Google 계정 > 보안에서 2단계 인증 켜기 → 앱 비밀번호 만들기(16자리). 개발용 테스트 계정 권장.
2. 네이버: 메일 환경설정에서 IMAP 사용 켜기, 2단계 인증 사용 시 애플리케이션 비밀번호 발급. 개발용 테스트 계정 권장.
3. 개발 환경: Rust(rustup + Visual Studio C++ 빌드 도구), pnpm(`corepack enable pnpm`). 관리자 권한이 필요할 수 있다.
4. 비밀값: `.env.example`을 복사해 `.env`에 작성. `.env`는 git에 올라가지 않는다.
5. 마일스톤마다 직접 실행해 보고 피드백은 구체적으로: "목록 행 높이가 디자인보다 8px 큼, 스크린샷 docs/design/fb-01.png".
6. 마일스톤마다 커밋해 체크포인트를 남긴다.

## 5. 세션 시작 템플릿

```
docs/plan.md의 <단계> <작업>을 진행해줘.
참고: docs/design/<화면>.dc.html
범위: <폴더/파일>
완료 기준: <테스트·동작>, /verify 통과
하지 말 것: <범위 밖>
```
