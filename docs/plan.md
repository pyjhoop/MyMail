## M5.1. 읽음 처리 UI 연결 (M5 후속)

- [x] 메일을 클릭해 본문을 열면 1초 뒤 `setRead(id, true)`로 읽음 처리 (안 읽음일 때만)
  - 1초가 지나기 전에 다른 메일을 고르거나 선택을 해제하면 취소한다 (방향키로 훑을 때 읽음 처리 방지)
  - 처리 뒤 메일 목록과 계정·폴더의 안 읽은 수를 다시 읽는다
  - 테스트: 1초 전 이동 시 호출 안 됨, 1초 뒤 한 번만 호출됨 (fake timers)

## M5.2. 메일 다중 선택·삭제 (M5 후속)

- [x] 메일 목록에서 여러 통 선택 (체크박스, Ctrl+클릭, Shift+클릭 범위 선택). 선택은 본문을 여는 클릭과 구분한다
  - 목록이 가상화되어 있어도 화면 밖 메일의 선택 상태가 유지된다
  - 폴더·계정을 바꾸면 선택을 해제한다
- [x] 선택된 메일 삭제 버튼 (선택이 있을 때만 활성, 선택 개수 표시). `deleteMail`을 선택한 메일마다 호출한다
  - 휴지통 밖의 메일은 휴지통으로 이동, 휴지통 안의 메일은 완전 삭제이므로 삭제 전에 확인 창을 띄운다(한국어 문구에 개수 표시)
  - 삭제 뒤 목록과 안 읽은 수를 다시 읽고 선택을 해제한다. 일부 실패하면 실패한 개수를 알린다
  - 통합 받은편지함에서도 동작한다 (메일이 속한 계정의 휴지통으로 이동)
  - 테스트: 선택·해제·범위 선택, 선택 0건일 때 삭제 버튼 비활성, 삭제 호출 횟수와 확인 취소 시 호출 안 됨

## M6. 작성·발송

- [x] 작성기(본문 영역 인라인), 주소 자동완성, 서명, 첨부
  - 새 메일·답장·전체 답장·전달, 보내는 계정 선택, 참조·숨은참조, 계정별 서명(편집 포함), 파일 첨부(서비스 용량 한도 검사)
  - 본문은 일반 텍스트다. 서식 편집(MAIL-11), 파일 끌어놓기 첨부는 아직 없다
- [x] 임시보관함 자동 저장, 발송·실패 처리
  - 입력이 1.5초 멈추면 임시저장하고, 임시보관함 목록에 서버 메일과 함께 보인다. 보내기는 SMTP(Gmail·네이버), 실패하면 "보내지 못함" 표시로 임시보관함에 남아 다시 보낼 수 있다
- 남은 것: 작성 창 분리(새 창, MAIL-18은 requirements상 2차), 서식 편집, 끌어놓기 첨부, 발송 취소·예약(2차). 실서버 발송 확인(Gmail·네이버 SMTP, 네이버가 보낸편지함에 사본을 남기는지)은 사용자가 요청할 때
